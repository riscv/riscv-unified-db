== Development

=== Run regression tests

To run all locally (takes a long time):

[source,bash]
--
./bin/regress
--

To list regression tests:

[source,bash]
--
./bin/regress --list
--

To run a specific regression test:

[source,bash]
--
# run the 'regress-sorbet' test
./bin/regress --name regress-sorbet
--

To run all regression tests matching a tag:

[source,bash]
--
# run all regressions tagged as 'smoke'
./bin/regress --tag smoke
--

=== Add a new regression

Basic Regressions::
--
Basic (most) regressions that can be run via the command-line within the UDB container are
stored in `tools/test/regress-tests.yaml`.

To add a basic regression, you must:

1. Add the regression in `tools/test/regress-tests.yaml`
    * The main steps of the test should go under the `test` key.
    * If there are any steps needed to set up the test in GitHub CI, add those under the `gh_pre` key.
    * If there are any steps needed after the test in GitHub CI, add those under the `gh_post` key.
2. run `./bin/chore gen regress`
--

See xref:regress-test-infrastructure.adoc[Regression test infrastructure] for more details.

Complex Regressions::
--
Complex regressions are not runnable on the command line. They only run in CI via GitHub Actions.

To add a complex regression, you must:

1. add the steps as a job in `tools/test/regress-gh-template.yaml`
2. run `./bin/chore gen regress`
--

See xref:regress-test-infrastructure.adoc[Regression test infrastructure] for more details.


=== Update Ruby gems

To update Ruby gems to the latest available versions, run:

[source,bash]
----
./bin/chore update gems
----

Then `git add` all updated/new files and make a PR.

=== Add a new Ruby gem

Add the gem in the appropriate gemspace or Gemfile (top, or one of the sub-project gems under tools/ruby-gems).

Install it:

[source,bash]
----
./bin/chore install gems # add '-t' option to avoid incrementing the container tag
----

=== Update the version of z3 used by udb

This requires docker/podman to run since it builds a portable binary using an old distro in a container.

[source,bash]
----
./bin/chore update z3
----

Check in the updates, and make sure to bump the version of the udb gem.

=== Build the container image

To build the development container image:

[source,bash]
----
./bin/chore container build
----

To force rebuild even if the container already exists:

[source,bash]
----
./bin/chore container build -f
----

=== Pull the container image

To pull the container image from the registry:

[source,bash]
----
./bin/chore container pull
----

To force pull even if the container already exists locally:

[source,bash]
----
./bin/chore container pull -f
----

=== Remove the container image

To remove the local container image:

[source,bash]
----
./bin/chore container remove
# or use the short form:
./bin/chore container rm
----

=== Add a new JSON-RPC method to the udb server

The udb JSON-RPC server uses a spec-first design: `tools/ruby-gems/udb/lib/udb/openrpc.yaml` is the single source of truth.
Adding a new method requires two edits — one to the spec, one to the handler module.

. *Add the method to `openrpc.yaml`*
+
Append a new entry under `methods:` with a `name`, `summary`, `params` list, `result` schema, and optional `errors` list.
For example, to add a `list_csrs` method:
+
[source,yaml]
----
  - name: list_csrs
    summary: List all CSRs for the configured architecture
    params: []
    result:
      name: csrs_result
      description: List of CSR names
      schema:
        type: object
        required: [csrs, count]
        properties:
          csrs:
            type: array
            items:
              type: string
          count:
            type: integer
            minimum: 0
    errors:
      - code: -32603
        message: Internal error
        data:
          type: string
----

. *Add a handler method to `json_rpc_handlers.rb`*
+
Add a method named `handle_<method_name>` (replace dots with underscores) to the `Udb::JsonRpcHandlers` module in
`tools/ruby-gems/udb/lib/udb/json_rpc_handlers.rb`.
The method receives a `params` Hash and must return a Hash matching the result schema.
The `@cfg_arch` instance variable provides access to the configured architecture.
+
[source,ruby]
----
sig { params(_params: T::Hash[String, T.untyped]).returns(T::Hash[String, T.untyped]) }
def handle_list_csrs(_params)
  csrs = @cfg_arch.csrs.map(&:name)
  { "csrs" => csrs, "count" => csrs.length }
end
----

The server validates at startup that every method in the spec has a corresponding handler; it will raise a `RuntimeError` if one is missing.

See `tools/ruby-gems/udb/JSON_RPC_SERVER.md` for full protocol details and client examples.

=== Generate Ruby type definitions

To generate Sorbet type definitions for all Ruby gems:

[source,bash]
----
./bin/chore gen ruby-type-def
----

To generate type definitions for a specific gem:

[source,bash]
----
./bin/chore gen ruby-type-def -g udb    # or idlc, or udb-gen
----
