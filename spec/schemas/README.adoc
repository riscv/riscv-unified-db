= Schema Versioning
:toc: left
:toclevels: 2
:sectnums:

== Overview

This directory contains the JSON schemas used to validate UDB data files.
Schemas are versioned so that data files can declare which schema version they
conform to, and so that older versions remain available as the schemas evolve.

== Directory Layout

----
spec/schemas/
├── README.adoc                  # this file
├── json-schema-draft-07.json    # unversioned copy of the JSON Schema Draft-07 meta-schema
├── <schema>.json -> v<X.Y>/<schema>.json   # symlinks to the current version
└── v<X.Y>/                      # one subdirectory per released version
    └── <schema>.json
----

The top-level `.json` files (except `json-schema-draft-07.json`) are *symbolic
links* that always point to the latest released version.  Consumers that want
stable, version-pinned references should use the versioned path inside the
appropriate `v<X.Y>/` subdirectory.

== Schema Identification (`$id`)

Every versioned schema file contains a top-level `$id` key whose value is the
canonical URL of that file in the repository:

[source,json]
----
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "$id": "https://github.com/riscv/riscv-unified-db/tree/main/spec/schemas/v0.1/<schema>.json",
  ...
}
----

The `$id` encodes both the schema name and its version, making it
unambiguous which version of a schema a data file was validated against.

== Special Files

`json-schema-draft-07.json`::
  A verbatim copy of the
  https://json-schema.org/draft-07/schema[JSON Schema Draft-07 meta-schema].
  It is *not* versioned alongside the UDB schemas and is left as a plain file
  in the top-level directory.  It carries its own `$id` assigned by the JSON
  Schema specification (`http://json-schema.org/draft-07/schema#`) and should
  not be modified.

== Releasing a New Schema Version

When breaking or significant changes are made to one or more schemas, a new
version should be released.  Follow these steps:

. Create a new subdirectory named `v<X.Y>` (e.g. `v1.0`).
. Copy the schemas that changed (or all schemas, for consistency) into the new
  subdirectory.
. Update the `$id` value in each copied schema to reflect the new version path.
. Re-point the top-level symlinks to the new subdirectory:
+
[source,bash]
----
cd spec/schemas
for f in v<X.Y>/*.json; do
  fname=$(basename "$f")
  ln -sf "v<X.Y>/$fname" "$fname"
done
----
. Add the new version to the <<Schema Versions>> table in this README.
. Keep the previous `v<X.Y>/` subdirectory intact so that existing data files
  that reference the old `$id` continue to validate correctly.
