<threat_model>
## Assets

- Phase-start bytes and `phase_start_baseline_sha256`.
- Exact allowlist and attribution classifications.
- Repository files outside the experiment boundary.

## Trust Boundaries

| Boundary | Untrusted input crossing it |
|---|---|
| Git index/worktree → baseline capture | filenames, modes, staged state, existing unrelated files |
| repository-relative request → filesystem open | traversal syntax, symlinks, special modes, mount crossings |

## Attacker capabilities

- Create prefix-collision paths, links, special files, or concurrent type changes.
- Modify a pre-existing unrelated file and attempt to hide or reattribute it.

## Abuse cases and mitigations

| Threat ID | STRIDE | Component | Severity | Disposition | Mitigation and verification |
|---|---|---|---|---|---|
| T-01-01 | Tampering | baseline capture | high | mitigate | exclusive first-write baseline, canonical hash, immutable-generation refusal; `test_filesystem_boundary` proves rewrite fails |
| T-01-02 | Tampering / Repudiation | delta classifier | high | mitigate | exact baseline comparison and explicit five-way classification; tests cover pre-existing, new, modified, and deleted paths |
| T-01-03 | Elevation / Disclosure | filesystem guard | high | mitigate | relative-POSIX validation plus `lstat` before open and special-kind rejection; adversarial fixtures prove fail-closed behavior |

ASVS target is L1-equivalent. Any unresolved high-severity result blocks the plan. The
package-legitimacy gate is not applicable because this plan installs no npm, pip, or cargo
package. Path traversal is security canon and remains covered here and by the later
`$gsd-secure-phase` hook; it is not minted as a bespoke prohibition.
</threat_model>
